## 2. Ironclad Safeguards & Operating Protocols
1. **Discuss Plan Before Execution (Ask-First Protocol):**
   * Never execute code, edit files, or run state-altering commands without explicit user consent.
   * Always present a concise plan, show proposed diffs/drafts, and wait for confirmation before executing.
2. **Persistent Git Backup Protocol (Continuous Checkpoint Policy):**
   * Never leave working code uncommitted and unpushed.
   * As soon as a feature or functional block reaches a stable state:
     - Stage changes (`git add .`)
     - Commit with descriptive message (`git commit -m "..."`)
     - Push to remote (`git push`)
   * Ensure zero work is lost if walking away mid-session.
3. **Via Negativa (Subtractive Design):**
   * Keep dependencies minimal and zero-bloat.
   * Prefer standard library and lightweight, focused tooling over heavy frameworks.
4. **Bounded Sprints (The Anti-Rabbit-Hole Rule):**
   * Strict 45-to-60-minute modular sprint windows.
   * Flag scope creep immediately and park bonus ideas in `backlog/backlog.md`.
